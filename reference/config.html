Config

Site Config

base

  • Type: string

  • Default: /

  • Details:

    The base URL the site will be deployed at.

    You will need to set this if you plan to deploy your site under a sub path. It should always start and end with a slash. For example, if you plan to deploy your site to GitHub pages at https://foo.github.io/bar/, then you should set base to "/bar/".

    The base is automatically prepended to the URLs that start with / in other options, so you only need to specify it once. (Except for attrs of head)

    Notice that base should be an absolute URL pathname starting and ending with / .

  • Also see:

    • Guide > Assets > Base Helper
    • Guide > Deployment

lang

  • Type: string

  • Default: en-US

  • Details:

    Language for the site.

    This will be the lang attribute of the <html> tag in the rendered HTML.

    This can be specified in different locales.

  • Also see:

    • Config > locales
    • Frontmatter > lang

title

  • Type: string

  • Default: ''

  • Details:

    Title for the site.

    This will be the suffix for all page titles, and displayed in the navbar in the default theme.

    This can be specified in different locales.

  • Also see:

    • Config > locales

description

  • Type: string

  • Default: ''

  • Details:

    Description for the site.

    This will be the content attribute of <meta name="description" /> tag in the rendered HTML, which will be overrode by the description field of page frontmatter.

    This can be specified in different locales.

  • Also see:

    • Config > locales
    • Frontmatter > description

head

  • Type: HeadConfig[]

  • Default: []

  • Details:

    Extra tags to inject into the <head> tag in the rendered HTML.

    You can specify each tag in the form of [tagName, { attrName: attrValue }, innerHTML?].

    This can be specified in different locales.

    Notice that if the attrValue is a pathname, it will be kept as-is without prepending base automatically, so remember to prepend it manually if needed.

  • Example:

    To add a custom favicon:

export default {
  head: [['link', { rel: 'icon', href: '/images/logo.png' }]],
}

Rendered as：

<head>
  <link rel="icon" href="/images/logo.png" />
</head>
  • Also see:
    • Config > locales
    • Frontmatter > head

locales

  • Type: { [path: string]: Partial<SiteLocaleData> }

  • Default: {}

  • Details:

    Specify locales for i18n support.

    Acceptable fields:

    • lang
    • title
    • description
    • head

  • Also see:

    • Guide > I18n

Theme Config

theme

  • Type: Theme

  • Details:

    Set the theme of your site.

    If this option is not set, the default theme will be used.

  • Also see:

    • Guide > Theme
    • Default Theme > Config

Bundler Config

bundler

  • Type: Bundler

  • Details:

    Set the bundler of your site.

    This option is required. vuepress-vite and vuepress-webpack are CLI shorthands that inject a default bundler (Vite and Webpack respectively). When you run the plain vuepress command, you need to set this option yourself, for example bundler: viteBundler().

    There is no vuepress-rspack shorthand. To use Rspack, install @vuepress/bundler-rspack and set bundler: rspackBundler().

  • Also see:

    • Guide > Bundler
    • Bundlers > Vite
    • Bundlers > Webpack
    • Bundlers > Rspack

Common Config

source

  • Type: string

  • Details:

    The absolute path of the site source directory.

    This option is required when using @vuepress/core programmatically. The CLI sets it to the directory passed to the command automatically, so you usually don't need to configure it in your config file.

dest

  • Type: string

  • Default: `${sourceDir}/.vuepress/dist`

  • Details:

    Specify the output directory for vuepress build command.

temp

  • Type: string

  • Default: `${sourceDir}/.vuepress/.temp`

  • Details:

    Specify the directory for temporary files.

Warning

Since VuePress will load temp files during dev and build, the temp directory should be inside project root to resolve dependencies correctly.

cache

  • Type: string

  • Default: `${sourceDir}/.vuepress/.cache`

  • Details:

    Specify the directory for cache files.

public

  • Type: string

  • Default: `${sourceDir}/.vuepress/public`

  • Details:

    Specify the directory for public files.

  • Also see:

    • Guide > Assets > Public Files

debug

  • Type: boolean

  • Default: false

  • Details:

    Enable debug mode or not.

    This would be helpful for developers. Also, we are using debug package for debug logging, which can be enabled via DEBUG=vuepress* environment variable.

pagePatterns

  • Type: string[]

  • Default: ['**/*.md', '!.vuepress', '!node_modules']

  • Details:

    Specify the patterns of files you want to be resolved as pages. The patterns are relative to the source directory.

permalinkPattern

  • Type: string | null

  • Default: null

  • Details:

    Specify the pattern to generate permalink.

    This will be overrode by the permalinkPattern field of page frontmatter.

  • Also see:

    • Frontmatter > permalinkPattern

userStyle

  • Type: string | null

  • Default: null

  • Details:

    Specify the path of a custom style file, which will be injected at the bottom of the client.

    Themes can also set this option, but user config takes precedence over theme config.

Build Config

shouldPreload

  • Type: boolean | ((file: string, type: string) => boolean)

  • Default: true

  • Details:

    A function to control what files should have <link rel="preload"> resource hints generated. Set to true or false to enable or disable totally.

    By default, only those files that are required by current page will be preloaded. So you can keep it true in most cases.

shouldPrefetch

  • Type: boolean | 'as-needed' | ((file: string, type: string) => boolean)

  • Default: 'as-needed'

  • Details:

    Controls which files get <link rel="prefetch"> resource hints.

    • 'as-needed' (default since v2.0.0-rc.32): only prefetch async resources of pages that are linked from the current page's Markdown content. This keeps the number of hints low on large sites.
    • true: prefetch async files of all other pages. This is good for small sites, which will speed up the navigation, but it might not be a good idea if you have lots of pages in your site.
    • false: disable prefetch hints entirely.
    • A function: return whether a file should be prefetched; it receives the file path and the resource type as arguments.

    The default was true in earlier 2.0.0-rc releases. Set it to true explicitly to restore the previous behavior.

templateBuild

  • Type: string

  • Default: '@vuepress/client/templates/build.html'

  • Details:

    Specify the path of the HTML template to be used for build.

templateBuildRenderer

  • Type: TemplateRenderer

  • Default: templateRenderer

  • Details:

    Specify the HTML template renderer to be used for build.

Markdown Config

markdown

  • Type: MarkdownOptions

  • Default: {}

  • Details:

    Configure VuePress built-in Markdown syntax extensions.

    It accepts all options of markdown-it, and the following additional options.

    Since v2.0.0-rc.32, VuePress uses markdown-it v15 and @mdit-vue v4. markdown-it ships its own type declarations (do not install @types/markdown-it), deep imports from markdown-it/lib/* are no longer supported, and MarkdownItEnv has been removed in favor of augmenting markdown-it.Env. See Plugin API > extendsMarkdown for migration details. The code option has been removed as well; see markdown.code.

  • Also see:

    • markdown-it > Init with presets and options
    • Guide > Markdown > Syntax Extensions

markdown.anchor

  • Type: AnchorPluginOptions | false

  • Default:

const defaultOptions = {
  level: [1, 2, 3, 4, 5, 6],
  permalink: anchorPlugin.permalink.headerLink({
    class: 'header-anchor',
    safariReaderFix: true,
  }),
}

  • Details:

    Options for markdown-it-anchor.

    Set to false to disable this plugin.

  • Also see:

    • Guide > Markdown > Syntax Extensions > Header Anchors

markdown.assets

  • Type: AssetsPluginOptions | false

  • Details:

    Options for VuePress built-in markdown-it assets plugin.

    Set to false to disable this plugin.

Caution

You should not configure it unless you understand what it is for.

markdown.assets.aliasSupport

  • Type: boolean | '@-prefix'

  • Default: true

  • Details:

    Use aliases for non-strict relative paths.

    This is a path that does not start with ./ or ../ or / or <protocol header>: <img src="path1/path2.png" />

    • If the option is true. path1 is regarded as an alias.
    • If the option is false. It is regarded as a relative path.
    • If the option is "@-prefix". If the path starts with @, path1 is regarded as an alias; Otherwise, it is regarded as a relative path.

markdown.assets.absolutePathPrependBase

  • Type: boolean

  • Default: true when using the Webpack or Rspack bundler, false when using Vite

  • Details:

    Whether to prepend base to absolute paths in Markdown.

    VuePress sets the default according to bundler.type: the Webpack and Rspack bundlers need it because they don't handle base for public files themselves, while Vite handles base for public files automatically. You should not configure it unless you know the asset paths have already been processed.

markdown.code

  • Type: never

  • Details:

    This option has been removed.

    Code block syntax highlighting is not built in. Use @vuepress/plugin-prismjs or @vuepress/plugin-shiki instead. See Guide > Markdown > Syntax Extensions > Code Blocks and Migration > For Users.

Please check out Plugin API Reference for a full list of Plugin APIs.
